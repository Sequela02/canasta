# Delegation responsibilities

These are responsibilities, not required agent names or a fixed team. Map only
what a task needs onto the environment's actual capabilities. One person or
agent may perform several responsibilities when independence is not required.
The coordinating agent retains scope, integration and user communication.

| Responsibility | When delegation earns its cost |
| --- | --- |
| Investigate | A specific ownership, dependency or context-heavy question blocks a decision. Return evidence, not a new implementation scope. |
| Advise | A difficult or expensive-to-reverse decision needs a materially different analysis. State assumptions and alternatives. |
| Implement | A bounded outcome has disjoint write ownership and an observable acceptance check. Preserve unrelated changes. |
| Verify | A finished candidate needs an independent requirement, behavior or integration check. Run checks against the adopted revision. |
| Review | A proposed or completed change needs skeptical defect analysis using only relevant lenses. Treat findings as hypotheses to substantiate. |
| Summarize | A large inventory or repetitive classification benefits from context isolation. Preserve source identity and uncertainty. |

Keep simple or tightly coupled work in the coordinating session. Parallelize
only independently verifiable work with non-overlapping mutable ownership.
Respect the environment's actual capacity and authority limits; do not invent
native roles, claim a child was started when it was not, or substitute a model
silently when an independent check is unavailable.

Inspect terminal outcomes before relying on children. Reconcile incomplete,
failed, cancelled and unknown states without calling them success. A follow-up
review should resolve a named disagreement, not collect another vote.

Before reporting completion, inspect proposed changes in the destination,
verify current scope and evidence, run the relevant checks and state any
unverified surface. Agreement between agents is not completion evidence.
