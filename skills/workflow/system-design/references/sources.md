# Sources behind the system-design procedure

- Requirements with numbers and failure-first thinking: Martin Kleppmann,
  *Designing Data-Intensive Applications* (reliability, scalability,
  maintainability); Google, *Site Reliability Engineering* (service level
  objectives, error budgets), https://sre.google/sre-book/table-of-contents/
- Start with a monolith: Martin Fowler, "MonolithFirst",
  https://martinfowler.com/bliki/MonolithFirst.html
- Prefer known technology: Dan McKinley, "Choose Boring Technology",
  https://boringtechnology.club/
- Diagrams: Simon Brown, the C4 model, https://c4model.com/
- Decision records: Michael Nygard, "Documenting Architecture Decisions",
  https://cognitect.com/blog/2011/11/15/documenting-architecture-decisions
- Skill shape: command-only, because design is a deliberate step and agents
  often skip skills they must choose to load (Vercel, "AGENTS.md outperforms
  skills in our agent evals", 2026); focused procedures over comprehensive
  documentation (SkillsBench, arXiv:2602.12670).
